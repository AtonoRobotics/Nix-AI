# W00 — Contract foundation

## Current scope

Issues #18–#20 implement W00.1–W00.3: import the governing v1.1 bundle unchanged,
expose the locked contract-development environment, validate every JSON Schema
and registry projection offline, and generate deterministic Protobuf descriptors
and Rust bindings. Remaining W00 traceability and qualification work is tracked
by Issues #21–#22.

## Components and files

- Immutable source: `Habitat-OS-Codex-Build-Bundle-v1.1/`
- Byte-identical projections: `CODEX-BUILD-SPEC.md`, `contracts/architecture/`,
  `contracts/proto/`, `contracts/schemas/`, and the root contract registries
- Locked environment: `flake.nix`, `flake.lock`
- Validation entry point: `tools/validate_contracts.py`
- Offline JSON Schema validator: `tools/schema_contracts.py`
- Protobuf generation and ABI validator: `tools/proto_contracts.py`
- Negative fixtures: `tests/fixtures/schema-contracts/` and
  `tests/fixtures/proto-contracts/`

## Boundaries and compatibility

The validator treats any source-manifest failure, projected-byte difference,
invalid declared metaschema, unresolved packaged reference, stale generated
binding, unexpected Protobuf formatting difference, or ABI regression as a hard
failure. Schema references resolve only from the in-memory `$id` registry and
never from the network. The governing Protobuf source's extra EOF newline is the
only permitted difference from canonical Buf formatting. This bootstrap
introduces no runtime authority, migrations, ABI, or compatibility policy.

## Tests and evidence

- `nix run .#validate-contracts`
- `nix flake check --show-trace`
- `python -m unittest discover -s tests -v`
- Negative fixtures prove malformed schemas, missing packaged references, and
  stale generated projections and an incompatible Protobuf field removal are
  rejected.
- A clean-checkout run is required before W00 itself may be marked passed.

## Rollback and blockers

Rollback removes only the bootstrap projections, flake, and validation wrapper;
the immutable source bundle remains the recovery source. No W00.1–W00.2 blocker is
known. The rest of W00 remains tracked by Issues #21–#22.
