# W02 — Authoritative state and evidence primitives

## Governing requirements

ARC-002, ARC-009, BLD-006, OBS-001–OBS-004, OBS-006, SEC-007, SEC-009,
and STA-001, STA-002, STA-005–STA-010.

## Public boundaries

- `StateStore.transition`: one transactional state/history command with optimistic
  concurrency, command idempotency, actor, UTC timestamp, correlation identity,
  and a verified evidence reference.
- `StateStore.history`: ordered append-only transition history. Corrections append
  a new transition linked by `correction_of`.
- `StateStore.put_evidence` and `verify_evidence`: SHA-256-addressed Garage S3 objects
  whose PostgreSQL references are immutable and independently rehashed on read.
- `StateStore.backup` and `restore`: common consistency-marker snapshots. Restore
  is disabled unless the caller constructs the store in dedicated recovery mode.
- Projection and migration status expose source lag and compatibility declarations.

PostgreSQL 17 is the single operational truth. Garage stores evidence bytes; an
object is never authoritative merely because it exists. Missing state or evidence
fails closed. Test reset and restore authority are opt-in construction parameters,
not ambient runtime operations.

## Qualification

`nix run .#apps.x86_64-linux.test-w02` creates digest-pinned disposable
PostgreSQL and the pinned Garage binary and verifies atomic crash points, concurrent
writers, immutable history, evidence tampering, backup corruption, database
restart, evidence-store outage, and recovery. It always removes only the uniquely
named containers it created.

The mandatory retained reports are `state-crash-matrix`,
`backup-restore-report`, and `evidence-integrity-report` under
`evidence/work-packets/W02/`.

## Rollback

Schema version 1 records forward/backward compatibility, interruption behavior,
and its rollback limit. Software rollback requires restoring a verified pre-v1
backup in recovery mode; ordinary runtime code cannot rewrite append-only history.
