## Current scope

Issues #18–#21 implement W00.1–W00.4: import the governing v1.1 bundle unchanged,
expose the locked contract-development environment, validate every JSON Schema
and registry projection offline, and generate deterministic Protobuf descriptors
and Rust bindings. Canonical requirement mappings, packet ownership, gate and

validated independently at the repository boundary. Remaining W00 qualification

## Boundaries and compatibility

The validator treats any source-manifest failure, projected-byte difference,
invalid declared metaschema, unresolved packaged reference, stale generated
binding, unexpected Protobuf formatting difference, or ABI regression as a hard
failure. Schema references resolve only from the in-memory `$id` registry and
never from the network. The governing Protobuf source's extra EOF newline is the
only permitted difference from canonical Buf formatting. This bootstrap
introduces no runtime authority, migrations, ABI, or compatibility policy.
At W00, an executable requirement mapping means a unique governing definition
with schema-valid ownership, criticality, implementation and enforcement
declarations, known gates, objective evidence names, acceptance text, and a live
source locator. Future-packet implementation paths and evidence artifacts are
declarations; W00 does not require those later deliverables to exist prematurely.

## Tests and evidence

- `nix run .#validate-contracts`
- `nix flake check --show-trace`
- `python -m unittest discover -s tests -v`
- Negative fixtures prove malformed schemas, missing packaged references, and
  stale generated projections, missing requirement mappings, invalid gates,
  dependency cycles, and an incompatible Protobuf field removal are rejected.
- A clean-checkout run is required before W00 itself may be marked passed.
