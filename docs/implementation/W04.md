# W04 — Identity and capability authority

W04 implements AUT-001 through AUT-010 in crates/habitat-authority. Typed
machine, service, and activation identities are authenticated before a
deterministic, default-deny evaluation. Every invocation is checked against
operation, target, time, generation, revocation epoch, and physical-enforcement
bounds. Decisions record subject, issuer chain, activation, objective, target,
operation, policy, state version, epoch, provider proof, and evidence identity.

Grant issuance requires independent approval. Delegation admits only children
whose operations, target prefix, lifetime, quota, generation, and remaining
depth are subsets of the parent. Agents cannot issue or approve wider authority
for themselves. Provider credentials are not represented in grants or
invocations and remain outside activation-visible inputs.

The authority ledger is atomically replaced after issuance, delegation, and
revocation. Revocation denial survives restart. Storage failure marks authority
unavailable, and all new decisions fail closed. Consequential requests also
require a verified physical-enforcement provider proof.

Run nix run .#test-w04 -- --evidence-dir PATH. Rollback preserves the authority
ledger and revocation epoch; deleting or rolling back revocations is forbidden.
