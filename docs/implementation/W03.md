# W03 — Agent ABI transport

## Contract and public boundary

W03 implements ABI-001 through ABI-010 in crates/habitat-abi. The canonical
habitat.agent.v1 Protobuf is compiled into tonic/prost server and client
bindings. The server accepts gRPC only over a protected Unix-domain socket,
requires kernel peer credentials, and negotiates compatible 1.x clients to
the implemented 1.0 semantic ABI. Unknown majors fail closed.

Every mutating request carries an activation-scoped command_id. The durable
ledger fingerprints the complete protobuf command, fsyncs an atomic replacement
before acknowledging commitment, returns the same result for exact duplicate
delivery, and rejects altered reuse with CONFLICT. Payloads are bounded to
1 MiB. Errors preserve class, retryability, authority impact, durable state,
and safe next action as structured status JSON.

The ABI requires explicit structured dispositions: transport completion,
process exit, or absent output never creates a completion claim. Context and
capability fields are immutable identifiers/descriptors in the activation
envelope; W03 introduces no capability authority or effect executor.

## Operations and rollback

habitat-abi-server SOCKET LEDGER creates a mode-0660 socket, loads the durable
ledger, and removes the socket after graceful shutdown. Rollback may replace
the binary with another ABI-major-1 implementation, but must preserve the
ledger and canonical protobuf field numbers. Breaking changes require a new
major package/service.

nix run .#test-w03 -- --evidence-dir PATH verifies the governing contracts
and emits abi-compatibility-report and duplicate-command-test.
