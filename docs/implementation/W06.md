# W06 — Execution isolation

W06 implements execution-profile admission and native process isolation in
crates/habitat-execution. Every request is admitted against declared runtime,
CPU, memory, storage, process, and timeout capacity before execution.

The qemu-x86-64-conformance profile declares only NATIVE. Its live boundary uses
new user, mount, PID, IPC, UTS, cgroup, and network namespaces; an immutable Nix
store; a single writable activation workspace; an empty environment; minimal
devices; and no host root, provider socket, peer workspace, or evidence mount.
Memory and file limits are kernel enforced. Cancellation targets the complete
process group and escalates to forced termination at a bounded deadline.

WASI, OCI, and microVM adapters enforce explicit-preopen and digest-pinning
construction rules, but remain declared absent for this profile. In particular,
the profile does not claim Firecracker qualification without KVM or OCI
qualification without a declared OCI runtime.

Run nix run .#test-w06 -- --evidence-dir PATH. The live adversarial suite must
pass before the native runtime can be declared qualified.
